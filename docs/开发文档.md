# 菜盒日记 开发文档

> 版本：1.2.0 ｜ 更新日期：2026-09-06 ｜ 框架：Flutter 3.32+ / Dart 3.8+

## 1. 项目简介

「菜盒日记」是一款温馨小清新的 Flutter 菜谱管理与随机点餐 App。核心玩法：把会做的菜记进菜谱库，纠结"今天吃什么"时用盲盒模式一键抽签，抽完自动生成饮食记录；新学的菜可以进入修炼模式反复迭代，满意后一键升级到正式菜库。

## 2. 架构总览

```
lib/
├── main.dart                          # 应用入口
├── models/                            # 数据模型（与 SQLite 表一一对应）
│   ├── dish.dart                      # 菜品
│   ├── category.dart                  # 分类
│   ├── meal_record.dart               # 饮食记录
│   └── practice_record.dart           # 修炼记录
├── database/
│   └── database_helper.dart           # SQLite 单例封装（含测试钩子）
├── services/
│   └── image_service.dart             # 菜品图片持久化管理
├── theme/
│   └── app_theme.dart                 # 暖棕色小清新主题
├── utils/                             # 纯逻辑工具（可单测）
│   ├── lottery.dart                   # 盲盒抽签算法
│   ├── meal_stats.dart                # 饮食统计计算
│   └── meal_type.dart                 # 餐次文案扩展
├── widgets/                           # 跨页面复用组件
│   ├── dish_image.dart                # 菜品图片（含占位图）
│   ├── star_rating.dart               # 五星评分（可交互/只读）
│   ├── image_source_sheet.dart        # 拍照/相册选择面板
│   └── category_edit_dialog.dart      # 分类新增/编辑弹窗
└── screens/
    ├── home_screen.dart               # 底部导航 + IndexedStack 主框架
    ├── recipe_library_screen.dart     # 菜谱库（搜索/分类管理）
    ├── blind_box_screen.dart          # 盲盒模式（抽签动画/避开近期吃过的菜）
    ├── meal_history_screen.dart       # 饮食记录（统计卡片/评价）
    ├── practice_screen.dart           # 修炼模式
    ├── add_dish_screen.dart           # 添加/编辑菜品
    ├── add_meal_record_screen.dart    # 手动记一餐（新增）
    └── dish_detail_screen.dart        # 菜品详情（搭配历史）
```

分层原则：

- **screens** 只负责 UI 与页面状态，数据通过 `DatabaseHelper` 获取；
- **utils** 内是纯函数/纯算法，不依赖 UI，全部可单元测试；
- **widgets** 是无状态复用组件，统一视觉与行为；
- **services** 封装跨页面的文件 I/O 副作用。

## 3. 数据模型与表结构

数据库文件 `cook_lottery.db`，version 1，四张表：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `categories` | `name`、`emoji`、`sort_order` | 菜品分类，首次启动预置 6 个默认分类 |
| `dishes` | `name`、`category_id`（FK）、`image_path`、`created_at` | 菜品 |
| `meal_records` | `date`（毫秒时间戳）、`meal_type`（lunch/dinner）、`dish_ids`（逗号分隔 ID）、`rating`、`notes` | 饮食记录 |
| `practice_records` | `dish_name`、`category_id`（FK）、`image_path`、`rating`、`is_promoted`、`promoted_dish_id`、`created_at` | 修炼记录 |

注意：`dish_ids` 采用逗号分隔文本存储（原始设计），查询"某菜品的搭配历史"时使用 `',' || dish_ids || ',' LIKE '%,id,%'` 整段匹配，避免 `5` 误匹配 `15`（见 4.1 修复清单）。解析统一走 `MealRecord.parseDishIds`。

## 5. 本次迭代：代码优化

1. **消除 N+1 查询**
   - 菜谱卡片/盲盒结果原来在 `build` 里对每个菜品发一次 `getCategory` 查询 → 改为页面加载时构建 `categoryById` 内存映射；
   - 饮食记录卡片原来对每条记录逐个 `getDish` → 改为 `getDishesByIds` 一次批量查询；
   - 盲盒页原来按分类逐个 `getDishesByCategory` → 改为一次 `getAllDishes` 后内存分组；
   - 修炼页原来先查菜名再按菜名逐个查记录 → 改为一次 `getAllPracticeRecords` 后内存分组。
2. **页面保活与刷新策略**：`HomeScreen` 改用 `IndexedStack` 保持四个页面状态（盲盒勾选、滚动位置不再丢失），页签切换时通过 `GlobalKey` 调用目标页 `reload()` 保证数据新鲜。
3. **去重**：分类新增/编辑两段几乎相同的弹窗代码合并为 `showCategoryEditDialog`；三处"拍照/相册"面板合并为 `showImageSourceSheet`/`pickAndPersistImage`；多处手写星级 `Row` 合并为 `StarRating`；五处手写 `File.existsSync + Image.file` 合并为 `DishImage`。
4. **抽签算法独立**：抽取逻辑抽为纯函数 `LotteryPicker.pick`，UI 与算法解耦，可被单元测试穷举验证。
5. **数据库 API 瘦身**：删除 6 个无人调用的方法（`getDishesByCategory`、`getDishCountByCategory`、`getMealRecordsByDate`、`getAllPracticeDishNames`、`getPracticeRecordsByDish`、统计三件套），新增 4 个实际使用的方法。
6. **测试基建**：`DatabaseHelper` 增加仅供测试的路径覆盖与重置钩子（`debugSetDatabasePath`/`debugReset`），使数据库层可在任意主机上用 `sqflite_common_ffi` 做真实 CRUD 测试。

## 6. 本次迭代：新功能

### 6.1 避开最近吃过的菜（盲盒页）

调研同类应用（CookBook 的 shuffle+exclude、Reddit「随机推荐但跳过最近做过的菜」需求）后发现这是同类产品的空白点。实现：

- 盲盒页新增开关与时间范围选择（1/3/7 天），默认开启 3 天；
- 抽签时查询 `getEatenDishIdsSince` 得到近 N 天吃过的菜品集合，`LotteryPicker` 优先排除；
- 某分类排除后无菜可抽时自动回退为该分类全部菜品，保证抽签总有结果。

### 6.2 手动记一餐（饮食记录页）

外出就餐、临时起意做的菜不需要经过盲盒，可直接点「记一餐」：

- 新页面 `AddMealRecordScreen`：餐次（午餐/晚餐）+ 日期选择器（默认今天，可选过去一年）+ 可搜索的菜品多选列表 + 可选心得；
- 保存后与盲盒生成的记录共用同一数据结构，评价/删除流程完全一致。

### 6.3 饮食统计卡片（饮食记录页）

列表顶部展示：总餐数、本周餐数、平均评分（星级 + 数值）、最常吃菜品 Top3（含次数）。计算逻辑抽为纯函数 `MealStats.compute`，可单测。

### 6.4 菜谱搜索（菜谱库）

AppBar 新增搜索按钮，展开按菜品名称过滤（不区分大小写），可与分类筛选叠加；搜索无结果时有独立空态文案。

### 6.5 抽签滚动动画（盲盒页）

点击抽签后先以 90ms/拍滚动展示随机组合约 0.8 秒再落定结果，增强"仪式感"（同类竞品如「吃么么」的转盘音效反馈即此类体验）。实现上使用可取消的 `Timer.periodic`，页面销毁时正确清理。

## 7. 图片生命周期

```
image_picker 临时文件
        │ ImageService.persist()（复制、改名为 uuid）
        ▼
<Documents>/dish_images/<uuid>.jpg    ← dish.image_path / practice_record.image_path 指向这里
        │
        ├─ 删除菜品 → ImageService.delete(imagePath)
        ├─ 删除分类 → 事务删除分类与菜品，按 DB 返回的路径逐个清理图片
        ├─ 换图     → 更新 DB 后清理旧图（保存失败则回收新图）
        ├─ 编辑页选图后取消保存 → dispose 时回收本次未保存的新图
        └─ 删除修炼记录 → 未升级的记录清理图片；已升级的记录比对菜库
                          菜品当前图片路径，仅在不被引用时清理（防孤儿文件）
```

`ImageService.delete` 只清理管理目录内的路径（按已解析目录全路径比对），对其它路径直接忽略，防御外部路径误删；清理失败只吞掉异常，不阻断业务。

## 8. 测试钩子说明

| 钩子 | 用途 |
|---|---|
| `DatabaseHelper.debugSetDatabasePath(path)` | 把数据库文件指到临时目录，测试互不干扰 |
| `DatabaseHelper.debugReset()` | 关闭连接并丢弃单例缓存，配合上一个钩子实现用例隔离 |
| `ImageService.debugSetRoot(dir)` | 把图片管理根目录指到临时目录 |

测试侧统一使用 `sqflite_common_ffi` 的 `databaseFactoryFfiNoIsolate`（当前 isolate 内同步执行，兼容 `flutter_test` 的 FakeAsync）。注意：sqlite3 动态库加载涉及真实异步 I/O，必须在 `setUpAll`（真实异步区）里通过 `initTestDatabaseFactory()` 预热，否则 Widget 测试会挂起。

## 9. 第二轮自检修复记录（2026-09-06）

对全项目做过一轮七维度自检（功能逻辑 / BUG / 边界异常 / 安全 / 性能 / 兼容性 / 错误处理）后，修复以下问题：

### 中风险

| # | 问题 | 修复方式 |
|---|---|---|
| M1 | 桌面端无 sqflite FFI 引导，启动即 MissingPluginException 无限加载 | `main.dart` 检测桌面平台时切换 `databaseFactoryFfiNoIsolate`；`sqflite_common_ffi` 移入 dependencies。注意：Windows 发行版需将 sqlite3.dll 放到可执行文件同级目录 |
| M2 | 全项目 0 处 try/catch，数据库异常时首屏无限转圈、写操作静默失败 | 四个主页 + 记一餐 + 菜品详情的加载逻辑全部包 try/catch，失败展示 `ErrorState`（含重试按钮）；全部写操作（保存/删除/升级/确认）失败时 `showErrorSnackBar` 提示，且不改变页面状态 |
| M3 | 选图链路（权限被拒/相机占用/复制失败）异常未捕获，表现为"点了没反应" | `pickAndPersistImage` 统一捕获并提示「获取图片失败，请检查相机/相册权限」；修炼弹窗选图改用该封装（顺带消除二次 persist 造成的重复拷贝） |
| M4 | 盲盒确认/添加菜品/修炼弹窗保存无防重复提交，双击产生重复数据 | 三处增加 `_isConfirming`/`isSaving` 守卫 + 按钮禁用态（记一餐此前已有） |

### 性能优化

- `DishImage` 缩略图按显示尺寸 × devicePixelRatio 设置 `cacheWidth`，避免整图解码占用内存；并增加 `errorBuilder` 兜底文件损坏场景。

## 10. 已知限制与后续方向

- `meal_records.dish_ids` 逗号分隔文本是历史设计，删除菜品后历史记录会显示「已删除的菜」；若未来支持关联表需数据库迁移（version 2 + `onUpgrade`）。
- 图片文件与数据库记录没有强一致校验，数据库被手动改动可能出现指向不存在文件的记录；UI 层已做占位图兜底。
- 可考虑的后续功能：数据导出/导入（JSON 备份）、深色模式、早餐餐次、菜品标签（辣度/荤素）。
